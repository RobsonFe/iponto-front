# LGPD in the Front-End

Personal data handling (Lei 13.709/2018). iPonto stores companies and employees: CNPJ, CPF, name, e-mail, phone, address and time records. Layer of [`/nextjs-review`](SKILL.md).

## Principles that affect UI code

| Principle | In practice |
|-----------|-------------|
| Necessidade (minimization) | Request, pass as props and render only what the screen needs |
| Finalidade | A new use of personal data needs a defined purpose: ask |
| Segurança | No exposure in storage, URL, log, cache or bundle |
| Transparência / livre acesso | The user can understand what is collected |
| Prevenção | Safe defaults: masked, not cached, not tracked |

## Never put personal data in

- URL paths or query strings (they reach history, logs and analytics). Search by CPF or e-mail goes in a request body through a Server Action.
- `localStorage`, `sessionStorage`, IndexedDB or readable cookies.
- `console.*`, error reporting, analytics events or session replay.
- `metadata`, `data-testid` or other attributes.
- A shared cache (`'use cache'` without a per-user key).
- Fixtures, mocks, screenshots or documentation with real people.

## Display

- Mask by default in lists; show the full value only where the task requires it.

| Data | Masked example |
|------|----------------|
| CPF | `***.456.789-**` |
| E-mail | `jo***@exemplo.com` |
| Phone | `(**) *****-1234` |

- Masking on the client does not protect data already sent: mask in the service when the screen does not need the full value.
- CPF, CNPJ and phone are `string`.

## Forms

- Correct `type` and `autoComplete`; do not enable autocomplete for other people's documents on shared screens.
- Validation messages never echo the full value of a document.
- Do not keep the data in global state after the flow ends.

## Test data

Use obviously fake values (`000.000.000-00` style or generated by a factory) and `@exemplo.com` addresses.

## Review questions

1. Which personal data enters this change?
2. Where does it travel: props, URL, cache, log, third party?
3. Is every field sent to the browser needed?
4. Who can see the screen, and is that enforced on the server?
5. Does a new external service receive the data? Ask first.

## Severity

Exposure in log, URL, storage, shared cache or third party: **Crítico**. Unneeded field sent to the client: **Obrigatório**.

Legal interpretation (legal basis, retention, data subject requests) is a question for the user, not a decision of the agent.
